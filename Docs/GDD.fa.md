## Game Design Document (GDD)

### Royal Flop — Social Casino Texas Hold’em (Android)

> **نام پروژه (موقت):** Royal Flop\
> &#x20;**نسخه سند:** 1.0\
> &#x20;**پلتفرم:** Android (API 24+) | **موتور:** Unity 2022.3 LTS | **زبان:** C#\
> &#x20;**رده سنی:** 18+ (Simulated Gambling)

---

### ۰. چشم‌انداز و ستون‌های طراحی

#### ۰.۱ Vision Statement

یک بازی پوکر تگزاس هولدم اجتماعی، سریع و روان برای موبایل که تجربه‌ی میز واقعی را با پیشرفت (Progression)، رقابت و ارتباط اجتماعی ترکیب می‌کند، **بدون هیچ‌گونه امکان نقد کردن یا برد و باخت پول واقعی**.

#### ۰.۲ ستون‌های طراحی (Design Pillars)

| ستون               | توضیح                                   | معیار موفقیت                               |
| ------------------ | --------------------------------------- | ------------------------------------------ |
| **سرعت و روانی**   | هر دست بازی روی موبایل کمتر از ۶۰ ثانیه | میانگین زمان هر دست ≤ ۴۵ ثانیه             |
| **عدالت و شفافیت** | شافل و توزیع کارت کاملاً سمت سرور       | صفر گزارش تقلب تأییدشده                    |
| **تعلق اجتماعی**   | بازیکن به دوستان و باشگاه خود وصل شود   | ≥ ۳۰٪ بازیکنان حداقل یک دوست دارند         |
| **پیشرفت ملموس**   | هر جلسه بازی حس پیشرفت بدهد             | ≥ ۸۰٪ جلسات با XP یا Quest همراه باشند     |
| **اقتصاد سالم**    | بازیکن رایگان هم بتواند بازی کند        | میانگین زمان ورشکستگی بازیکن F2P ≥ ۴۸ ساعت |

#### ۰.۳ مخاطب هدف

| بخش            | مشخصات                                                     |
| -------------- | ---------------------------------------------------------- |
| سن             | ۱۸ تا ۵۵ سال                                               |
| پروفایل اصلی   | علاقه‌مند به پوکر، بازیکن Casual تا Mid-core               |
| الگوی بازی     | ۳ تا ۵ جلسه در روز، هر جلسه ۱۰ تا ۲۵ دقیقه                 |
| بازارهای اولیه | ترکیه، برزیل، هند، اروپا، خاورمیانه (با رعایت قوانین محلی) |

### ۱. Core Gameplay Loop

#### ۱.۱ چرخه‌ی کلان (Macro Loop)

```
ورود به بازی → دریافت Daily Bonus → لابی → انتخاب میز/تورنمنت
      ↑                                                  ↓
 خرید/تبلیغ ← کمبود چیپس ← دریافت جایزه/XP ← بازی (چند دست)
```

#### ۱.۲ جزئیات هر مرحله

| مرحله             | رفتار بازیکن                         | سیستم‌های درگیر                    | هدف طراحی                       |
| ----------------- | ------------------------------------ | ---------------------------------- | ------------------------------- |
| **۱. ورود**       | Login (Guest / Google / Facebook)    | Auth، Daily Bonus                  | کمتر از ۱۰ ثانیه تا لابی        |
| **۲. لابی**       | مشاهده میزها، Quest، رویدادها        | Matchmaking، Quest، Events         | نمایش واضح مسیر بعدی            |
| **۳. انتخاب میز** | Quick Seat یا انتخاب دستی            | Level Gate، Buy-in                 | کمتر از ۳ تپ تا نشستن پشت میز   |
| **۴. بازی**       | Fold / Check / Call / Raise / All-in | Game State Machine، Hand Evaluator | تصمیم‌گیری سریع، ۱۵ ثانیه Timer |
| **۵. جایزه**      | دریافت پات، XP، پیشرفت Quest         | Economy، Progression               | بازخورد بصری و صوتی فوری        |
| **۶. تکرار**      | ادامه روی همان میز یا تغییر میز      | Retention Hooks                    | ایجاد انگیزه‌ی «یک دست دیگر»    |

#### ۱.۳ چرخه‌ی هر دست (Micro Loop)

1. **Waiting / Seating** → 2. **Post Blinds** → 3. **Deal Hole Cards** → 4. **Pre-flop Betting** → 5. **Flop** → 6. **Turn** → 7. **River** → 8. **Showdown** → 9. **Payout** → 10. **Cleanup**

> این مراحل مستقیماً به **Game State Machine** در Phase 1 نگاشت می‌شوند (State Pattern + Eventهای `OnStateChanged`، `OnPotAwarded` و غیره).

#### ۱.۴ Retention Hooks

- **کوتاه‌مدت:** Quest روزانه، Daily Bonus، Spin Wheel
- **میان‌مدت:** Level Up، باز شدن میز جدید، Battle Pass
- **بلندمدت:** Leaderboard فصلی، Club Events، Collection آیتم‌های ظاهری

### ۲. Game Modes

#### ۲.۱ Cash Game (چیپس مجازی)

| ویژگی               | مقدار                                                     |
| ------------------- | --------------------------------------------------------- |
| تعداد صندلی         | 2 (Heads-up)، 6 (Short-handed)، 9 (Full Ring)             |
| Buy-in              | حداقل ۲۰ تا حداکثر ۱۰۰ بیگ‌بلایند                         |
| ورود/خروج           | آزاد، Rebuy مجاز                                          |
| Rake (کارمزد مجازی) | ۳٪ از هر پات، سقف مشخص (به‌عنوان Chip Sink)               |
| ربات‌ها             | در صورت کمبود بازیکن واقعی تا ۳۰ ثانیه، ربات اضافه می‌شود |

**سطوح میزها:**

| سطح | نام         | Blinds (SB/BB)    | Buy-in حداقل | Level لازم |
| --- | ----------- | ----------------- | ------------ | ---------- |
| 1   | Rookie      | 50 / 100          | 2,000        | 1          |
| 2   | Amateur     | 250 / 500         | 10,000       | 5          |
| 3   | Pro         | 1,000 / 2,000     | 40,000       | 12         |
| 4   | Expert      | 5,000 / 10,000    | 200,000      | 20         |
| 5   | High Roller | 25,000 / 50,000   | 1,000,000    | 30         |
| 6   | VIP Elite   | 100,000 / 200,000 | 4,000,000    | 40 + VIP   |

**رفتار ربات‌ها (Bot AI):** سه پروفایل Tight-Aggressive، Loose-Passive و Balanced. ربات‌ها **نباید** در میز با بازیکنان واقعی بدون برچسب ظاهر شوند (الزام شفافیت). در رتبه‌بندی و جوایز Leaderboard شرکت نمی‌کنند.

#### ۲.۲ Tournament

##### الف) Sit & Go (SNG)

| ویژگی          | مقدار                                            |
| -------------- | ------------------------------------------------ |
| شروع           | به‌محض پر شدن صندلی‌ها (6 یا 9 نفر)              |
| Buy-in         | ۱ تا ۱۰۰ برابر BB پایه (بر اساس سطح)             |
| Starting Stack | ۱,۵۰۰ تا ۵,۰۰۰ تورنمنت‌چیپ (جدا از چیپس اصلی)    |
| Blind Levels   | افزایش هر ۳ دقیقه (Turbo) یا ۵ دقیقه (Regular)   |
| ساختار جایزه   | ۶ نفره: 50/30/20 — ۹ نفره: 45/30/25 (نفر ۱ تا ۳) |

##### ب) Scheduled Tournament

| نوع                | زمان‌بندی          | ظرفیت           | جایزه                |
| ------------------ | ------------------ | --------------- | -------------------- |
| Daily Freeroll     | هر روز ساعت ثابت   | نامحدود         | چیپس + XP            |
| Evening Main Event | روزانه ۲۰:۰۰ (UTC) | تا ۵۰۰ نفر      | چیپس + آیتم ظاهری    |
| Weekend Special    | جمعه/شنبه          | تا ۲,۰۰۰ نفر    | جایزه‌ی ویژه + Badge |
| Club Championship  | ماهانه             | اعضای باشگاه‌ها | جایزه‌ی باشگاهی      |

**نکته‌ی حقوقی مهم:** جایزه‌ی تورنمنت‌ها فقط چیپس مجازی، آیتم ظاهری یا Badge است. هرگز جایزه‌ی نقدی، Gift Card یا کالای واقعی تعریف نشود.

#### ۲.۳ Private Table (میز خصوصی)

| ویژگی          | توضیح                                                                       |
| -------------- | --------------------------------------------------------------------------- |
| ساخت میز       | انتخاب Blinds، تعداد صندلی، Timer و رمز ورود                                |
| دعوت           | از طریق کد ۶ رقمی، لینک Deep Link یا لیست دوستان                            |
| تنظیمات میزبان | حذف بازیکن، توقف بازی، تغییر Blinds                                         |
| هزینه‌ی ساخت   | رایگان تا ۳ ساعت؛ بیشتر از آن با VIP یا هزینه‌ی چیپس                        |
| Rake           | ۰٪ (جهت تقویت جنبه‌ی اجتماعی)                                               |
| ربات           | قابل فعال/غیرفعال‌سازی توسط میزبان                                          |
| محدودیت        | میز خصوصی XP کاهش‌یافته (۵۰٪) می‌دهد تا سوءاستفاده (Chip Dumping) محدود شود |

### ۳. Economy Design

#### ۳.۱ اصول اقتصادی

1. چیپس **Soft Currency** است و قابل تبدیل به پول واقعی نیست.
2. یک **Hard Currency** (الماس / Gems) برای خرید آیتم‌های ظاهری و Battle Pass تعریف می‌شود.
3. اقتصاد باید طوری باشد که بازیکن F2P با تبلیغات و Bonus بتواند در سطوح پایین ادامه دهد.

#### ۳.۲ چیپس اولیه (Starting Balance)

| مورد                    | مقدار                    |
| ----------------------- | ------------------------ |
| Welcome Bonus (ثبت‌نام) | **50,000** چیپس          |
| پاداش آموزش (Tutorial)  | +10,000 چیپس             |
| Gems اولیه              | 20 Gem                   |
| **جمع اولیه**           | **60,000 چیپس + 20 Gem** |

> با ۶۰,۰۰۰ چیپس، بازیکن می‌تواند حدود ۳۰ Buy-in در میز Rookie داشته باشد که برای یادگیری کافی است.

- **Lucky Spin:** روزانه یک چرخش رایگان؛ جایزه‌ها از ۱,۰۰۰ تا ۱۰۰,۰۰۰ چیپس. **احتمال هر جایزه باید در UI نمایش داده شود** (الزام Google Play برای مکانیک‌های تصادفی پولی/شانسی).

### ۴. Progression System

#### ۴.۱ Level و XP

**منابع XP:**

| فعالیت                   | XP          |
| ------------------------ | ----------- |
| بازی یک دست (Cash)       | 10          |
| برد یک دست               | +15         |
| برد با Showdown          | +10         |
| Hand قوی (Flush به بالا) | +50 تا +500 |
| پایان SNG (Top 3)        | 100 تا 300  |
| تکمیل Quest روزانه       | 50 تا 200   |
| Daily Login              | 25          |

**فرمول نیاز XP برای Level بعدی:**

```
XP_required(L) = 100 × L^1.6      (L = سطح فعلی)
```

| Level   | XP لازم برای سطح بعد | XP تجمعی (تقریبی) |
| ------- | -------------------- | ----------------- |
| 1 → 2   | 100                  | 100               |
| 5 → 6   | 954                  | \~2,400           |
| 10 → 11 | 3,981                | \~14,000          |
| 20 → 21 | 12,000               | \~90,000          |
| 30 → 31 | 23,000               | \~280,000         |
| 50      | سقف اولیه (Soft Cap) | —                 |

**پاداش Level Up:** چیپس (`5,000 × Level`)، Gem در سطوح ۵، ۱۰، ۲۵، ۵۰ و Unlock ویژگی جدید.

### ۷. Technical Architecture

#### ۷.۱ معماری کلان (Client-Server)

```
┌────────────────────────┐         ┌──────────────────────────────┐
│  Unity Client (Android)│         │         Backend              │
│  ─ View (UI, Anim)     │◄──WSS──►│  Game Server (Authoritative) │
│  ─ Controller          │         │  ─ Table Manager             │
│  ─ Model (Pure C# Core)│◄──HTTPS►│  ─ Matchmaking               │
│  ─ Network Adapter     │         │  ─ Tournament Engine         │
└────────────────────────┘         │  Meta Services (REST)        │
                                   │  ─ Auth, Profile, Shop, IAP  │
                                   │  ─ Social, Quests, Economy   │
                                   └──────────┬───────────────────┘
                                              │
                          ┌───────────────────┼──────────────────┐
                       PostgreSQL           Redis           Analytics/Logs
                     (داده‌ی ماندگار)   (Session، Cache)   (BigQuery / ClickHouse)
```

**اصول کلیدی:**

1. **Server Authoritative:** شافل، توزیع کارت، محاسبه‌ی برنده و پات فقط در سرور.
2. **Shared Core Library:** منطق Pure C# (Card، Deck، HandEvaluator، StateMachine) به‌صورت یک `.NET Standard 2.1` Library هم در کلاینت (پیش‌نمایش/UI) و هم سرور استفاده شود. این همان چیزی است که در Phase 1 می‌سازید.
3. **Client Dumb:** کلاینت فقط نمایش می‌دهد و Action ارسال می‌کند؛ هر Action اعتبارسنجی می‌شود.
4. **Event-Driven:** پیام‌ها به‌صورت Event (`PlayerActed`، `CardsDealt`، `PotAwarded`).
5. **شافل امن:** استفاده از `RandomNumberGenerator` (CSPRNG) با Fisher-Yates؛ نه `System.Random`.

#### ۷.۲ انتخاب شبکه: Photon PUN2 یا سرور اختصاصی؟

| معیار              | Photon PUN2                        | Photon Fusion / Quantum | سرور اختصاصی (مثلاً Nakama یا .NET) |
| ------------------ | ---------------------------------- | ----------------------- | ----------------------------------- |
| سرعت توسعه         | ⭐⭐⭐⭐⭐                              | ⭐⭐⭐                     | ⭐⭐                                  |
| امنیت (Anti-Cheat) | ⭐⭐ (Master Client)                 | ⭐⭐⭐⭐                    | ⭐⭐⭐⭐⭐                               |
| کنترل اقتصاد/منطق  | ضعیف                               | متوسط                   | کامل                                |
| هزینه‌ی اولیه      | کم (CCU-based)                     | متوسط                   | زیرساخت + نگهداری                   |
| مقیاس‌پذیری        | خوب (تا حد CCU خریداری‌شده)        | خوب                     | بسیار خوب (با طراحی درست)           |
| وضعیت پشتیبانی     | **Maintenance Mode** (فقط رفع باگ) | فعال                    | بسته به انتخاب                      |
| مناسب پوکر؟        | برای MVP بله، برای Production خیر  | نسبی                    | **بهترین**                          |

**ملاحظات صادقانه:**

- Photon PUN2 مدل Master-Client دارد؛ یعنی یکی از کلاینت‌ها «میزبان» منطق است. در پوکر، شافل یا محاسبه‌ی برنده روی کلاینت یعنی **امکان تقلب و دستکاری چیپس**. اگر از PUN2 استفاده می‌کنید، منطق حساس را حتماً به سرور خودتان منتقل کنید.
- Photon خودش PUN2 را در حالت نگهداری معرفی کرده و برای پروژه‌های جدید Fusion را پیشنهاد می‌کند (قبل از تصمیم نهایی وضعیت فعلی را در سایت Photon بررسی کنید).

**پیشنهاد معماری (Hybrid / مرحله‌ای):**

| فاز               | رویکرد                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| **MVP (ماه ۱–۳)** | بازی آفلاین با ربات + Core Logic کامل (Phase 1 فعلی). برای تست مولتی‌پلیر، PUN2 فقط به‌عنوان Transport |
| **Soft Launch**   | سرور مستقل Authoritative (Nakama یا .NET + WebSocket) برای منطق میز؛ Photon/Nakama برای Realtime       |
| **Production**    | مهاجرت کامل منطق به Game Server، Photon (در صورت ادامه) فقط Relay/Matchmaking                          |

#### ۷.۴ امنیت و Anti-Cheat

| تهدید                    | راهکار                                                     |
| ------------------------ | ---------------------------------------------------------- |
| تقلب در کارت             | شافل CSPRNG سمت سرور؛ ارسال فقط Hole Cards همان بازیکن     |

| Reverse Engineering      | IL2CPP، Obfuscation، عدم ذخیره‌ی منطق حساس در کلاینت       |

#### ۷.۵ ملاحظات عملکرد روی Android

- **GC-free در Update:** Object Pooling برای کارت‌ها، چیپس‌ها و Eventها؛ پرهیز از LINQ و `string` concatenation در حلقه‌ها.
- **Struct به‌جای Class** برای `Card` (مثلاً یک `byte` یا `readonly struct`) و Hand Evaluator مبتنی بر Bitmask / Lookup Table.
- **Addressables** برای بارگذاری آیتم‌های ظاهری.
- **Texture Atlas و ASTC Compression**؛ هدف حجم نصب زیر ۱۵۰ مگابایت.
- **هدف FPS:** ۶۰ روی دستگاه‌های میان‌رده، ۳۰ حداقل در دستگاه‌های ضعیف.
- **Network:** پروتکل باینری (MessagePack/Protobuf)، Reconnect خودکار و بازیابی وضعیت میز.
